# 解析局面からミニゲームへ渡す仕様

この文書は、解析画面から独立したミニゲームへ局面を渡すための実装契約です。既存動作への影響を避けるため、解析エンジンとミニゲームの状態・計算は分離します。

## 目的と範囲

- 解析画面で入力したカードとボードを、ミニゲームの開始局面として使えるようにする。
- 対象モードは「ハンド指定」と「相手想定」。
- 解析勝率は開始時点の参考値として表示するだけで、ゲーム中に再計算しない。
- DealScopeの解析機能にアクション助言・GTO・EV判断を追加しない。
- 通常のミニゲーム開始・進行・次ハンド動作を変更しない。

## 局面の受け渡し

- 解析画面の状態を独立したスナップショットとして複製する。ミニゲームから解析側の状態オブジェクトを直接変更しない。
- 受け渡しには同一タブの `sessionStorage` を使う。ホールカードをURL、ログ、クエリ文字列へ書き込まない。
- ミニゲーム開始前にペイロードのバージョン、モード、プレイヤー数、カード枚数、カードID、ボード枚数、カード重複を検証する。
- 検証失敗時は解析画面に留まり、具体的なエラーを表示する。部分的な状態でゲームを開始しない。
- 解析画面へ戻るときは保存したスナップショットを復元する。ゲーム中に解析状態を書き換えない。
- 解析画面へ戻ってから再びゲームを開始した場合、前のゲーム状態を再開せず、保存済みの元の解析局面から新しく開始する。
- ハンド終了後は「次のハンドへ」と「解析画面へ戻る」を明示的に選べる。タイマーだけで画面を遷移させない。

## 開始ストリート

| Board入力 | 開始位置 |
|---|---|
| 0枚 | Preflop。通常のミニゲーム開始処理を使う |
| Flop 3枚 | Flop開始 |
| Turnまで4枚 | Turn開始 |
| Riverまで5枚 | River開始 |

Flop以降は過去のプリフロップや前ストリートのアクションを再現しない。開始ストリートのベット額は全員0とし、入力したポット総額を開始ポットとして扱う。

## プレイヤーとカード

- 解析に含まれるプレイヤーだけを開始時の参加者とする。解析に含まれない座席はフォールド済みとして扱い、行動・配牌・勝敗判定に参加させない。
- 「ハンド指定」では、入力済みの各プレイヤーのホールカードを開始ハンドに固定する。
- 「相手想定」ではHeroのホールカードだけを固定し、相手は残りデックから重複なくランダムに配る。
- 既知の相手カードは、配牌・カード重複チェック・ショーダウン判定にだけ使う。CPUの行動判断には渡さず、CPUが自分のカードと公開情報以外を参照できないようにする。
- 次のハンドでは固定カードを引き継がず、通常のランダム配牌へ戻す。
- 解析開始時の勝率は「開始時の解析勝率」と明記し、ゲーム中の現在勝率と誤認させない。

## ポット・スタックの安全条件

ポット総額だけでは、過去の各プレイヤーの投入額やフォールドしたプレイヤーの投入額、過去のサイドポット階層は復元できない。そのため、過去のベット履歴は推測で再現しない。

### 基本設定と詳細設定

- **基本設定**では入力項目を増やさず、残りスタックは既存ミニゲームの初期値（各プレイヤー1,000）を使う。
- Flop以降の開始ポットは既定値を10,000とする。
- **詳細設定**を開いた場合だけ、開始時の各参加プレイヤーの残りスタックと開始ポットを個別に調整できる。
- 詳細設定を使わなければ、デフォルト値のまま開始できる。値はゲーム開始前に確認できるようにする。
- スタックとポットは0以上の有限な整数とし、空欄・負数・不正値・上限超過は開始前にエラー表示する。入力値を無言で丸めたり置き換えたりしない。

### チップ会計モデル

- インポートされた開始ポットは、過去の投入履歴から再構成したポットではなく、**開始時点に存在する独立したポット額**として扱う。
- 開始時の残りスタックと開始ポットの合計を、このインポートゲーム内のチップ総量とする。開始ポットの配当と、その後のベット・コール・レイズ・オールインは、この総量を増減させない。
- 開始ポットは全ての開始参加者が争う共通ポットとして扱い、通常のプレイヤー別拠出額から作るサイドポットとは分けて配当する。ショーダウン時には開始ポットを対象プレイヤーの最良ハンドに配当し、その後、通常の拠出額から作った各ポット階層を既存ロジックで配当する。
- 1人を除く全員がフォールドした場合は、開始ポットとそのハンドで実際に拠出された額を残ったプレイヤーが獲得する。
- 解析に含まれない座席は参加者に含めず、開始スタックを割り当てず、配牌・行動・配当から除外する。
- これは過去のトーナメント履歴を復元する機能ではない。入力した残りスタックと独立した開始ポットを使うシミュレーションであり、過去のサイドポットやフォールド済みプレイヤーの拠出内訳は再現しない。
- インポートされたハンドが終わった後に「次のハンドへ」を選んだ場合は、以降を通常ミニゲームの新しいハンドとして扱い、解析から固定したホールカードを引き継がない。解析画面へ戻る場合は、保存した元の解析スナップショットを復元する。

### ポット入力UI（Flop以降）

- 基本設定では「開始ポット 10,000」を表示し、必要な場合のみ詳細設定を開いて変更する。
- 詳細設定内に、参加中プレイヤーそれぞれの残りスタック入力欄を設ける。省略時は各人1,000。
- ポットとスタックは直接入力でき、増減ボタンも用意する。増減幅の既定値は1,000とする。
- 入力値は「開始ポット」「開始時の残りスタック」と明示し、過去の投入額や実際の履歴と誤認させない。

## 必須の回帰テスト

1. 既存の通常スタートが従来どおり動く。
2. Preflop / Flop / Turn / River の開始位置がそれぞれ一致する。
3. 同じカードがHero、相手、ボードに重複している場合は開始を拒否する。
4. ハンド指定の固定相手カードがCPU判断ロジックに漏れない。
5. 相手想定のランダム配牌にカード重複がない。
6. 解析に含まれない座席は配牌・行動・ショーダウンから除外される。
7. 解析へ戻った後、モード・プレイヤー数・全カード・ボードが完全一致する。
8. 解析へ戻って再開した場合、前のゲーム状態・スタック・乱数状態を引き継がない。
9. 開始ポットはサイドポットと分離して配当され、スタック合計＋ポット合計がハンドを通じて保存される。フォールド勝利とショーダウンの両方で検証する。
10. 既存の回帰検証とCIを通す。

## ブランチ運用

この仕様は `feature/analysis-minigame-bridge` 上で管理する。解析本体の既定ブランチや通常ミニゲームの動作へ、検証前の変更を直接入れない。


## 実装・検証メモ

実装済み（連携ブランチ上）:

- 解析結果の下に「この局面でミニゲーム」を追加。局面スナップショットと開始時勝率は同一タブの `sessionStorage` で渡し、カードを追加のURLパラメータやログへ書き込まない。
- ミニゲーム開始前にデータ形式、人数、カードID、重複、ボードの並び、開始勝率を検証。不正データは開始せず、設定画面にエラーを表示する。
- 基本設定は残りスタック各1,000、Flop以降の開始ポット10,000。ポットと参加者別スタックの変更は詳細設定内。入力は0〜1,000,000,000の整数として検証する。
- 解析済みカードを固定して開始。相手想定ではHeroだけを固定し、相手は残りデックから配る。非参加座席は除外。CPUの意思決定関数は自分のホールカードと公開情報のみ参照する。
- 開始ポットを拠出額由来のサイドポットと分離し、フォールド勝利・ショーダウンの両方で配当する。
- ハンド終了時は自動で次へ進めず、「次のハンドへ」「解析画面へ戻る」を表示。元の解析状態は戻り先で復元し、次ハンドは固定カードなしの通常配牌に戻す。
- 検証中に既存ショーダウン処理のサイドポット階層生成が `Set` を配列要素として扱う不具合を発見し、数値配列へ変換するよう修正。
