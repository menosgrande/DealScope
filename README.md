# DealScope

DealScope は、ホールカードとボードを入力すると、現在のカード勝率を表示する小型Webツール。
SPECTRAとは独立しており、レンジ・GTO・戦略解説などは扱いません。詳しい仕様は [SPEC.md](SPEC.md) を参照。

## 4人トーナメント・ミニゲーム\n\n`minigame.html` はCalculatorとは分離した遊び用の4人トーナメントです。プレイヤー1人＋CPU 3人で、スタック1000、ブラインド上昇、脱落、ショーダウン、サイドポットまで含む1テーブル・トーナメントを最後の1人まで進めます。\n\nCPUはGTO戦略ではありません。TAG / LAG / タイト・パッシブ / ルーズ・パッシブの4タイプを、参加率・レイズ率・コール率・ブラフ傾向・プレッシャー傾向としてパラメータ化し、ハンド強度、ボード、ポットオッズ、スタック、ストリート、ランダムな揺らぎを組み合わせて行動します。タイプ名はキャラクターとして表示しますが、行動は確率的です。\n\n役判定は本体の `engine.js` を共有し、ミニゲーム固有のUI・進行・CPU判断は `minigame.html` / `minigame.js` に閉じ込めています。本体の「GTO・アクション判断を扱わない」という仕様には追加しません。\n\n## 使い方

1. 画面下の「カードを選ぶ ▲」を押してカードピッカーを開く(閉じるときは「閉じる ×」)
2. カードを選ぶと、次の未入力枠へ自動で移動する
3. ハンド指定では、P1〜P4を横並びにし、各列を「名前 → ホールカード → 勝率 → いま作れている役」の順に表示する。下に勝率の100%積み上げバーを表示する。相手想定はHeroを縦型で表示する。ボードは Flop(3枚) → Turn → River の順に、横一列で入力する。Flopが3枚そろうまでTurn、Turnが入るまでRiverは新しく入力できない

- 入力済みの枠をタップすると選び直せる(「外す」で空にもできる)。入力中の枠は、カードの上の ▼(上下に動く)で示す
- ピッカー上部の ‹ › で、カードを選ばずに前の枠・次の枠へ移れる
- 他の枠で使用中のカードはピッカーで選べない
- 画面右上の `?` でヘルプを開く
- Handの「配る」は、**空欄だけ**をランダムなカードで埋める(入力済みのカードは変わらない)。Handの「↻ 全体」は表示中のプレイヤーのハンド2枚を引き直す。「× 全消去」は表示中のプレイヤーのハンドを消す。各プレイヤーの「↻ / ×」では、そのプレイヤーだけを引き直す / 消去する。いずれも直後の7秒間は「元に戻す」で元の状態へ戻せる。相手想定で隠れているハンド指定側のカードは、表示中のHand操作では変更しない。
- Boardの「↻ 全体」は、プレイヤーのカードを残してボード5枚だけをランダムに引き直す。各ストリートのカード右にある「↻」では、Flop・Turn・Riverのその部分だけを引き直し、後ろのストリートは保持する。「× 全消去」はBoardだけをすべて消す。各ストリートの「×」はそのストリートから後ろを消す(FlopならFlop〜River、TurnならTurn〜River、RiverならRiver)。いずれも直後の7秒間は「元に戻す」で元の状態へ戻せる。
- 入力中のカードは端末に保存され、リロードしても復元される

## モード

| モード | 人数 | 入力 | 計算 |
|---|---|---|---|
| ハンド指定 | 2〜4人 | 全員のカード2枚 | Exact(完全列挙) |
| 相手想定 | 相手1〜4人(最大5人卓) | Hero のカード2枚だけ | 相手1人でFlop以降: Exact / それ以外: Monte Carlo(`≈` 付き) |

- 人数を変更しても、非表示になったプレイヤーのカードは保持される。3人→2人→3人のように戻すと、元の入力が復活する。モードを切り替えても入力は残り、ハンド指定 → 相手想定 → ハンド指定と戻ると P1〜P4 が復活する(相手想定の Hero はハンド指定の P1 と同じ枠)
- 復活するとき、Board・Hero と同じカードが重なっていたら、隠れていた P2〜P4 側を空欄にする
- 相手想定は、相手のカードがランダムだと仮定した勝率。Monte Carlo(100,000回)の数字は実行のたびに少し変わる
- 計算するのは、ボード0枚(Preflop) / Flop3枚 / +Turn / +River のとき。Flopが1〜2枚の入力途中などは「入力待ち」

## 近似値(≈)とモンテカルロ法

相手想定の `≈` が付いた数字は、カードをランダムに100,000回配って勝敗を数えた近似値(モンテカルロ法)。実行のたびに数字が少し変わり、ずれは最大で±0.3ポイント程度(1σは0.16ポイント以下)。試行回数を4倍にしても、誤差は半分にしかならない。手順・誤差の見積もり・速度・検証は [SPEC.md](SPEC.md) の「12. 付録: Monte Carlo シミュレーションの詳細」を参照。

## 最終役

勝率の下の「最終役 ▼」を開くと、最終役をプレイヤーごとに分析できる。

- **勝率の内訳**(デフォルト): 各ランアウトで得たequityを、そのランアウトの最終役ごとに分けた割合。各列の合計は、そのプレイヤーの総勝率(equity)になる
- **成立率**: 起こりうる全パターンのうち、そのプレイヤーの最終役がその役になる割合。各列の合計は100%
- 上部の [勝率の内訳] [成立率] を切り替えて、同じ役×プレイヤー表を別の指標で見られる
- ハンド指定はExact、相手想定の近似(`≈`)はMonte Carloの集計
- 相手想定モードの列は「Hero」と「相手(1人あたり)」

## 光るカード

Flop以降、全員のカードがそろうと、**全員の中でいちばん強いハンドの5枚**が金色の線で囲まれる(それ以外のカードは暗くなる。ボード3枚+手札2枚 / ボード4枚+手札1枚 / ボード5枚、など)。各プレイヤーの最強を全員分光らせるわけではない。同じ強さのプレイヤーがいるときは、その全員のカードが光る。

## 勝率の定義

引き分けは取り分を等分して計算する(ポット分配を考慮したequity相当)。

## URL

入力状態はURLの `#` 以降に反映される(開くだけで同じ局面を再現できる)。

```
#AdTs-2c7h                      ハンド指定2人。P1 = A♦T♠、P2 = 2♣7♥
#AdTs-2c7h/Kh7d3s/Qc/2h         + Flop K♥7♦3♠ + Turn Q♣ + River 2♥
#AdTs-2c7h-KdKs                 ハンド指定3人
#AdTs-??-??/Kh7d3s              相手想定(相手2人) + Flop
```

- `P1[-P2[-P3[-P4]]]/Flop/Turn/River`。相手想定は `Hero-??[-??…]`(`??` が相手1人)
- カードは「ランク(`AKQJT98765432`)+スート(`shdc`)」の2文字。読み込み時は大文字小文字を区別しない。空欄は `xx`、末尾の空欄は省略できる
- 何も入力していない2人は `#` なし。3人は `#--`、4人は `#---`、相手想定は `#xx-??`
- 重複したカードは後ろを空欄にして読み込む。URLが無い・不正なときは端末の保存内容から復元する
- URLに入るのは、いま表示しているモードの入力だけ(相手想定のURLに、隠れている P2〜P4 は入らない)。端末の保存には隠れた分も含めて残る。リロードで同じURLを開くと隠れた分も戻るが、他の人のURLには持ち込まれない
- 入力のたびのURL更新は履歴を増やさない(「戻る」でカードが1手ずつ戻らない)
- 静的ホスティング(GitHub Pages など)で動くよう、パスではなく `#` 形式にしている

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | 画面・スタイル・ヘルプ |
| `app.js` | カード入力UI / カード状態 / 結果表示 / 保存 |
| `state.js` | 入力状態の純関数(URLの書き出し・読み込み / 重複の整理 / 保存データの検証 / 配る・Hand/Boardの引き直し・消去)。UI非依存 |
| `engine.js` | 役評価・Exact・Monte Carlo・最強の5枚。UI非依存、外部依存なし |
| `verify.js` | 検証コード。ヘルプの奥「開発者向け」を開いたときだけ読み込まれる |

## 検証

`?` → 一番下の「開発者向け: 計算の検証」を開く。

- **計算が正しいか確認**: 5枚役の全分布の照合 / 別方式の評価器との勝敗照合 / 既知ケース(正解値・Exact・Monte Carlo) / 相手想定(別方式での数え直し、厳密値との照合) / 最終役(成立率・勝率の内訳の別方式判定・Monte Carloとの照合) / 入力状態の整理(重複の整理・URLの往復・保存データ・配る)
- **計算速度を測る**: Exactの所要時間。スマートフォン実機で測ること

既知ケースの `expected` は、ルールから確定できる値か手計算の値のみ。`expected: null` は、外部の信頼できる計算機の値を入れる枠(サイト名・URL・取得日・条件・引き分けの扱いを併記すること)。推測値は入れない。

## 動かし方

静的ファイルのみ。`index.html` を開くか、GitHub Pages などにそのまま置く。ビルド不要。


## 開発ロードマップ

現行仕様と今後の構想を混ぜない。以下は**未実装の計画**であり、現在の動作仕様ではない。

### Phase 0 — 仕様固定
現行のモード名、Hand / Board 操作、最終役、UI方針、README / SPEC の同期を維持する。

### Phase 1 — UI検証
320〜430pxを中心に、はみ出し・重なり・縦方向の増加をヘッドレスChromiumで確認し、スクリーンショットと数値で記録する。最終的な見た目の判断は実機・人間が行う。

### Phase 2 — UI・入力操作完成
カードピッカー、カード削除、‹ ›、配る、Hand / Board の個別・全体操作、Undo、人数変更、モード変更など、入力時の引っかかりをなくす。

### Phase 3 — レンジ仕様
相手レンジの表現、コンボ、ウェイト、厳密計算 / Monte Carlo の境界を SPEC で先に確定する。

### Phase 4 — レンジ実装
確定したレンジ仕様を、エンジン → verify.js → UI の順で実装する。

### Phase 5 — 勝ち方分析
最終役の集計を「勝ち・引き分け・負け」に分け、どの役が勝敗にどう寄与したかを確認できるようにする。

### Phase 6 — アウト表示
アウトを勝率とは別の指標として定義し、「アウト = 必ず勝てるカード」ではないことが分かるUIにする。実装前に SPEC を更新する。

### Phase 7 — 履歴・お気に入り
よく使う局面を少数保存し、一覧から呼び出せるようにする。URL共有を置き換えるのではなく補完する。

### Phase 8 — プレイヤー名
P1 / P2 などを任意の名前に変更できるようにする。

### 追加しない機能
GTO・アクション判断・EV計算・複雑なベットシミュレーション・派手な装飾は、DealScope の対象外とする。

※ Phase 3〜4 のレンジ機能は、上記の順序だけを固定し、今回の「レンジ系以外」の更新では実装しない。
